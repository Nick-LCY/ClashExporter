# 0003. JSON 快照持久化

- 日期：2026-10-26
- 状态：已接受
- 背景：
  exporter 重启后内存账本清零，而 mihomo 侧仍然存活的连接累计值不变。若从零开始归账，这部分已经累计在连接上的字节会被当作新增量重复计入，导致流量虚高；若完全不恢复，则重启窗口内新产生的流量永久丢失，总量低估。因此需要把账本状态跨进程重启保留下来。
- 决策：
  - 账本全部状态（含活跃连接表、站点集合、全局对账值）默认每 30 秒原子写盘一次：同目录临时文件 → 写 JSON → `fsync` → `rename` → 父目录 `fsync`。
  - 收到 SIGTERM / SIGINT 时强制写一次快照再退出；启动时若快照存在则恢复。
  - 快照必须包含活跃连接表。否则重启后现存的存活连接会被当成「首次出现」而全量计入，造成流量虚高。
  - 快照文件为单个 JSON，默认路径 `./data/state.json`。
- 影响：
  - 重启后计数器不归零，Prometheus 端无断档，配合 [[architecture/decisions/0001-单表全维度计数器.md]] 的计数器语义成立。
  - 需要一个可写目录；生产部署使用 `/var/lib/clash-exporter/state.json`。
  - 原子写保证任何时刻中断都不会读到半截 JSON；写失败时删除临时文件并保留旧快照。
  - 停机期间产生的流量天然不可追溯——恢复后只能看到 mihomo 侧仍然累计在存活连接上的字节，这部分属于已知的信息损失边界。
