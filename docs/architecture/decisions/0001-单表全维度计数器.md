# 0001. 单表全维度计数器

- 日期：2026-10-26
- 状态：已接受
- 背景：
  用户的核心问题是「每台机器、每个网站、在每个代理节点上各消耗了多少流量」，本质是设备、站点、节点三个维度的交叉统计。常见做法有两种：一是 exporter 预聚合出多张表（设备表、站点表、节点表），二是 exporter 只导出最细粒度的单表，把统计口径交给 Prometheus 查询时聚合。预聚合表看似直观，但同一份流量会在多张表里重复落盘（存储翻倍），且每新增一种统计口径就要新增一张表和一套归账逻辑；单表方案只保存一份事实数据，所有口径在查询侧决定。
- 决策：
  - 核心指标只有一张表 `clash_traffic_bytes_total{device, site, proxy, direction}`，`direction` 取 `upload` 或 `download`，账本中每个条目产出两条时间序列。
  - 维度切片统计全部交给 Prometheus 查询时聚合，使用 `sum by (...)` 与 `increase(...)`。
  - exporter 不预聚合、不产出第二张交叉表。
  - 全局对账指标独立命名为 `clash_traffic_total_bytes_total{direction}`，与核心指标不同名，避免朴素求和时与核心指标混淆或双算。
- 影响：
  - 查询灵活性最高，新增统计维度不需要改 exporter，只需换 PromQL。
  - 序列基数约等于「活跃组合数 × 2」，稳态下为万级，必须配合 [[architecture/decisions/0002-无损淘汰与重锚.md]] 的淘汰机制把暴露面限制住；站点维度另有去重上限（默认 10000，超限归入 `other` 桶，`other` 不占配额）。
  - 用户需要具备基本的 PromQL 使用能力，README 必须给出常用查询示例。
  - 语义约束：核心指标是计数器，值只增不减，跨 exporter 重启与跨 stale 间隙都不能出现下降或缺口丢数。
